# 운영 및 배포

## 로컬 개발 환경 시작하기

### 백엔드

```bash
cd backend
uv sync
uv run uvicorn main:app --reload --port 8000
```

| 항목 | URL |
|------|-----|
| API 서버 | http://localhost:8000 |
| Swagger UI | http://localhost:8000/docs |

### 프론트엔드

```bash
cd frontend
npm install
npm run dev
```

프론트엔드는 http://localhost:5173 에서 서비스됩니다.  
백엔드(`http://localhost:8000`)가 먼저 실행 중이어야 합니다.

---

## 환경 변수 설정

### 프론트엔드 (Vercel / 로컬 `.env`)

| 변수 | 설명 | 예시 |
|------|------|------|
| `VITE_API_BASE_URL` | 백엔드 API 서버 주소 | `https://plan-buddy-zlpu.onrender.com` |

> 로컬 개발 시 기본값은 `http://localhost:8000` 으로 하드코딩되어 있어 `.env` 파일 없이도 동작합니다.

### 백엔드 (Render / 로컬 `backend/.env`)

| 변수 | 설명 | 기본값 | 필수 |
|------|------|--------|------|
| `DATABASE_URL` | DB 연결 문자열 | SQLite (`./sql_app.db`) | 운영 시 필수 |
| `SECRET_KEY` | JWT 서명 키 | `campus_calendar_dev_key_1234` | 운영 시 필수 |
| `FRONTEND_URL` | 프론트엔드 배포 주소 (CORS) | — | Render 배포 시 |
| `NAVER_CLIENT_ID` | Naver Open API Client ID | — | 장소 검색 API 사용 시 |
| `NAVER_CLIENT_SECRET` | Naver Open API Client Secret | — | 장소 검색 API 사용 시 |

> **SECRET_KEY**: 운영 환경에서는 반드시 충분히 복잡한 랜덤 문자열로 교체해야 합니다. 기본값 사용 시 JWT 보안 취약.  
> **NAVER_CLIENT_ID / SECRET**: [Naver Developers](https://developers.naver.com/apps/) 에서 앱 등록 후 **검색** API를 활성화하면 발급됩니다. 미설정 시 `/places/search` 엔드포인트가 503을 반환하지만, 프론트엔드는 Nominatim을 직접 호출하므로 장소 검색에는 영향 없음.

## CORS 설정

현재 백엔드(`main.py`)에서 `allow_origins=["*"]`를 적용 중입니다.  
보안 강화 시 `FRONTEND_URL` 환경변수를 활용하여 특정 도메인으로 제한할 수 있습니다.

## 백엔드 배포 (Render)

| 항목 | 값 |
|------|----|
| 플랫폼 | Render (Web Service) |
| 런타임 | Python 3 |
| 빌드 명령어 | `pip install -r requirements.txt` |
| 실행 명령어 | `uv run uvicorn main:app --host 0.0.0.0 --port 10000` |

> `uv`가 Render 빌드 환경에 없는 경우 대안: `uvicorn main:app --host 0.0.0.0 --port 10000`

### Render 환경 변수 (필수)

| 변수 | 값 |
|------|----|
| `DATABASE_URL` | Render PostgreSQL 접속 URL (또는 Supabase) |
| `SECRET_KEY` | 충분히 복잡한 랜덤 문자열 |
| `FRONTEND_URL` | `https://plan-buddy-seven.vercel.app` |

### Render PostgreSQL

Render Free Tier의 PostgreSQL은 별도 애드온으로 제공됩니다.  
`DATABASE_URL`은 Render PostgreSQL 인스턴스의 **Internal Database URL**을 사용하세요.

## 데이터베이스 관리

### SQLite → PostgreSQL 마이그레이션

개발에서 운영으로 전환 시 스키마는 `Base.metadata.create_all()` 로 자동 생성됩니다.  
운영 데이터 이관이 필요한 경우 별도 스크립트 작성이 필요합니다.

### SQLite 스키마 변경 주의사항

SQLAlchemy의 `create_all()`은 **새 테이블만 생성**하며 기존 테이블에 컬럼을 추가하지 않습니다.  
개발 중 모델에 컬럼을 추가한 경우:

**방법 1 — DB 파일 재생성 (데이터 손실)**
```bash
rm backend/sql_app.db
# 서버 재시작 시 자동 생성
```

**방법 2 — ALTER TABLE (데이터 보존)**
```python
import sqlite3
conn = sqlite3.connect('backend/sql_app.db')
conn.execute('ALTER TABLE events ADD COLUMN radius REAL DEFAULT 50.0')
conn.commit()
conn.close()
```

> **실제 사례**: `Event` 모델에 `radius` 컬럼 추가 후 기존 DB에서 모든 캘린더 API가 500 에러를 반환하는 문제가 발생. `ALTER TABLE`로 해결.

### Render Free Tier SQLite 주의

Render Free Tier는 **재배포 시 파일 시스템이 초기화**됩니다.  
SQLite를 운영에 사용하면 배포할 때마다 모든 데이터가 삭제됩니다.  
**운영 환경에서는 반드시 PostgreSQL을 사용하세요.**
