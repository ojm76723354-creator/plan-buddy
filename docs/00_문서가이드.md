# 문서 가이드

## 목적
이 문서는 Plan Buddy 프로젝트의 문서화 기준과 원칙을 정의합니다. 모든 팀원은 이 가이드에 따라 문서를 작성하고 유지보수합니다.

## 업데이트 원칙
- **업데이트 주기**: 매일 새로운 기능이 추가되거나 기존 아키텍처/명세가 변경될 때마다 관련 문서를 즉시 업데이트합니다.
- **버전 관리**: 모든 문서는 Git 저장소의 `docs/` 디렉토리 내에서 코드와 함께 버전 관리됩니다.

## 문서 목록 및 역할
1. `00_문서가이드.md`: 문서 작성 원칙 및 템플릿
2. `01_시스템개요.md`: 프로젝트 목적, 주요 대상, 전체 시스템 아키텍처 개요
3. `02_기능설계.md`: 유스케이스, 기능 요구사항 명세
4. `03_데이터베이스설계.md`: ERD, 테이블 스키마
5. `04_API명세.md`: REST API 엔드포인트 명세
6. `05_업무플로우.md`: 핵심 비즈니스 로직 및 사용자 시퀀스 흐름
7. `06_프론트엔드구조.md`: Vue.js 기반 프론트엔드 아키텍처
8. `07_백엔드구조.md`: FastAPI 기반 백엔드 아키텍처
9. `08_운영배포.md`: Vercel, Render 배포 및 환경변수 가이드
10. `09_위험요소_및_개선포인트.md`: 기술 부채, 알려진 버그, 향후 개선 사항

## 템플릿 기본 양식
모든 문서는 Markdown 포맷으로 작성하며, 가독성을 위해 다음과 같은 기본 양식을 따릅니다.
- 제목 1 (`#`) : 문서의 메인 제목 (파일 내 1개만 존재)
- 제목 2 (`##`) : 주요 섹션
- 제목 3 (`###`) : 세부 항목
