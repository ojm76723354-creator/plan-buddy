# 위험 요소 및 개선 포인트

## 현재 기술적 부채 (Technical Debt)
1. **테스트 코드 부재**: 현재 단위 테스트(Unit Test)나 통합 테스트(Integration Test)가 부족함. 기능 추가 시 사이드 이펙트를 방지하기 위해 Pytest(백엔드) 및 Vitest(프론트엔드) 도입 필요.
2. **에러 처리 고도화**: API에서 발생하는 다양한 에러(DB 연결 실패, 검증 오류 등)에 대한 중앙 집중식 에러 핸들링 및 로깅 체계가 미흡함.

## 알려진 이슈 / 위험 요소
1. **CORS 설정**: 로컬 개발 환경과 배포 환경의 URL이 다를 경우 CORS 정책 충돌 위험이 있음. 동적인 origin 관리가 필요함.
2. **토큰 보안**: JWT 토큰을 현재 LocalStorage에 저장할 경우 XSS 공격에 취약할 수 있음. HttpOnly 쿠키 방식으로 전환 고려 필요.
3. **SECRET_KEY 기본값**: 개발용 키(`campus_calendar_dev_key_1234`)가 코드에 하드코딩되어 있음. 운영 배포 시 반드시 환경 변수로 교체해야 함.

## 해결된 이슈 (Fix Log)

### [2026-05-12] 라이트 모드에서 월간/주간/일간 버튼 텍스트 미표시 문제
- **증상**: 라이트 모드 전환 시 캘린더 뷰의 월간/주간/일간 탭 버튼과 헤더의 뷰 전환 버튼(btn-outline) 텍스트가 흰색으로 표시되어 보이지 않음.
- **원인**: `vue-cal` 라이브러리 내부 메뉴 버튼(`.vuecal__menu li`)의 텍스트 색상이 기본적으로 흰색으로 설정되어 있었으며, 글로벌 `.btn-outline` 클래스의 `color` 값이 `var(--text-primary)`를 따르더라도 라이브러리 스타일에 덮어씌워지지 않음.
- **해결**: `CalendarView.vue`의 `<style scoped>` 내에 아래 두 가지 스타일 추가:
  1. `:deep(.vuecal__menu li) { color: var(--text-primary) !important; }` — vue-cal 내부 탭 텍스트 색상 강제 지정
  2. `:root:not([data-theme='dark']) .btn-outline { color: #1e293b; }` — 라이트 모드에서 btn-outline 텍스트 어둡게 고정
- **관련 파일**: `frontend/src/views/CalendarView.vue`

### [2026-06-02] 네이버 지도 API 인증 실패 (401 Unauthorized) 문제 해결
- **증상**: 네이버 지도 설정(Client ID, 서비스 URL)이 정확함에도 배포 환경 및 로컬에서 지도가 하얀 박스로만 표시되며 401 인증 실패 에러가 발생함.
- **원인**: 네이버 클라우드 플랫폼의 **통합 콘솔(Global/VPC)** 전환으로 인해 기존 파라미터(`ncpClientId`)와 구형 엔드포인트(`openapi.map.naver.com`) 지원이 중단되었으나, 레거시 문서를 참조하여 개발한 것이 원인.
- **해결**: 최신 통합 규격에 따라 엔드포인트를 **`oapi.map.naver.com`**으로, 파라미터를 **`ncpKeyId`**로 변경하여 해결.
- **안정성 강화**: 모달 애니메이션 등 UI 전환 시 지도가 비정상적으로 초기화되는 문제를 방지하기 위해 `nextTick()` 및 `naver.maps.Event.trigger(map, 'resize')` 로직을 추가하여 렌더링 내구성을 높임.
- **관련 파일**: `frontend/index.html`, `frontend/src/components/NaverMapSelector.vue`, `frontend/src/views/LiveMeetingView.vue`

### [2026-06-08] SQLite `radius` 컬럼 누락으로 전체 캘린더 API 500 에러
- **증상**: 모든 `GET /calendar/` 요청이 500 Internal Server Error를 반환. DB에 `events` 테이블은 존재하나 컬럼이 맞지 않음.
- **원인**: `Event` 모델에 `radius` 컬럼이 추가된 후 `create_all()`이 호출되었지만, `create_all()`은 기존 테이블에 새 컬럼을 추가하지 않음. 이미 생성된 `sql_app.db`는 구버전 스키마를 유지.
- **해결**: Python `sqlite3`로 수동 마이그레이션:
  ```python
  import sqlite3
  conn = sqlite3.connect('sql_app.db')
  conn.execute('ALTER TABLE events ADD COLUMN radius REAL DEFAULT 50.0')
  conn.commit()
  conn.close()
  ```
- **관련 파일**: `backend/models.py`, `backend/sql_app.db`

### [2026-06-08] 친구 캘린더 조회 엔드포인트 미구현으로 404 에러
- **증상**: 프론트엔드에서 `GET /calendar/friends/{username}` 호출 시 404 반환.
- **원인**: `calendar_router.py`에 해당 엔드포인트가 구현되지 않아 있었음.
- **해결**: `calendar_router.py`에 친구 캘린더 엔드포인트 추가. 공개 범위(visibility) 필터링 로직 포함:
  - ACCEPTED 친구: `PUBLIC` + `FRIENDS_ONLY` 이벤트 반환
  - 비친구: `PUBLIC` 이벤트만 반환
  - `PRIVATE` 이벤트는 항상 제외
  - **주의**: 라우트 등록 순서가 중요. `/{event_id}` 보다 앞에 `/friends/{username}` 를 등록해야 충돌 없음.
- **관련 파일**: `backend/routers/calendar_router.py`

### [2026-06-08] 채팅 메시지가 LiveMeetingView에 표시되지 않는 버그
- **증상**: 채팅 메시지를 전송하고 GET으로 조회 시 API에서는 데이터가 반환되지만, 화면에서 메시지가 아예 표시되지 않음. 말풍선 영역 자체가 렌더링되지 않음.
- **원인 1**: `LiveMeetingView.vue` 템플릿에서 `localStorage.getItem('username')`을 직접 호출. Vue 렌더러가 `localStorage`를 인스턴스 프로퍼티로 인식하지 못해 "Property 'localStorage' was accessed during render but is not defined on instance" 경고 발생 → 렌더 에러로 해당 블록 전체 숨겨짐.
- **원인 2**: `auth.js`의 `login()` 함수가 `localStorage`에 `token`만 저장하고 `username`은 저장하지 않아, 로그인 후 `username`을 `localStorage`에서 읽을 수 없었음.
- **해결**:
  1. `LiveMeetingView.vue`: 모듈 최상위에서 `const myUsername = localStorage.getItem('username') || ''` 로 추출, 템플릿에서 `myUsername` 사용.
  2. `auth.js` `login()` 함수: 토큰 저장과 동시에 `localStorage.setItem('username', username)` 추가.
  3. `auth.js` `logout()` 함수: `localStorage.removeItem('username')` 추가.
- **관련 파일**: `frontend/src/views/LiveMeetingView.vue`, `frontend/src/api/auth.js`

## 향후 개선 사항
1. **알림 기능**: 친구 요청이나 일정이 공유되었을 때 실시간 알림(WebSocket 또는 SSE) 도입.
2. **성능 최적화**: 일정이 많아질 경우 캘린더 렌더링 성능 저하 가능성. 데이터 페이지네이션이나 캐싱(Redis 등) 도입.
3. **CI/CD 파이프라인**: GitHub Actions를 통한 자동화된 빌드 및 테스트 구축.
4. **배포 환경 안정성**: 프론트엔드-백엔드 간 CORS 에러 및 환경 변수(`VITE_API_BASE_URL`) 미설정 시 통신 불가. CI/CD 파이프라인에서 빌드 전 환경 변수 체크 스크립트 추가 검토.
5. **모바일 배터리 최적화**: 지속적인 GPS 폴링은 배터리 소모를 유발할 수 있으므로, Geofencing API 및 OS 수준의 백그라운드 최적화 지원 필요.
6. **DB 마이그레이션 도구**: 현재는 스키마 변경 시 `ALTER TABLE`을 수동으로 실행해야 함. Alembic 도입으로 자동화 필요.
